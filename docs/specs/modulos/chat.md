# Módulo `cincel-chat`

Panel de chat sobre GPUI. Consume `AgentEvent` y emite `AgentCommand` (`03-arquitectura.md §3`). Diseño en `02-visual.md §7`.

## Estructura
- `ChatPanel` (entidad): `connections: Vec<ChatConnection>`, `active_connection: Option<String>`, `preselected_connection`, `banner: Option<ConnectionBanner>`, `conversations`, `transcript: Vec<Entry>`, `input`, `config_options`. (Sin `autonomy`: se retiró en la Etapa 3, la política de permisos es fija y vive en el workspace. Sin selector de agentes ni `ChatAgent`: se retiraron en la Etapa 4, ver "Conexiones".)
- `Entry`: `UserMessage { blocks }`, `AgentText { markdown, streaming }`, `AgentThought { text, collapsed, duration }`, `ToolCall { id, kind, title, status, content: Vec<ToolContent>, locations, stats: Option<(u32,u32)> }`, `Plan { items }`, `Permission { request_id, tool_call, options, answered }`, `AuthRequired { methods }`, `Notice { level, text }`, `TurnSeparator { stop_reason, duration }`.
- Markdown: componente de `gpui-kit` en modo streaming; código con resaltado de `cincel-syntax`; botón copiar por bloque.
- Tarjeta de herramienta de edición: muestra path y `+N −M` (de `ReviewStore::stats`), botón "Ver en el editor" → `workspace::open_and_jump(path, first_pending_hunk)`. **No renderiza el diff completo**: como mucho las 3 primeras líneas de contexto al desplegar, con la nota "Revisá en el editor".
- Permisos: botones en el orden que envía el agente; `Enter` elige el primero; `Esc` elige la primera opción `reject_*`; al responder, la tarjeta se compacta a una línea "Permitido / Rechazado".
- Input: un `cincel_editor::EditorView` configurado como campo de texto Markdown (sin gutter, ajuste de línea, resaltado de estructura con los tokens de sintaxis, fences con fondo `bg.editor` y monoespaciados; ver `02-visual.md` §7), crece hasta 8 líneas; `Enter` envía, `Shift+Enter` salto; `@` abre el selector de archivos del proyecto (filtro por subcadena, v1 sin fuzzy); `/` abre comandos del agente; arrastrar desde el árbol inserta mención (una imagen se adjunta como imagen desde la Etapa 7, `ChatPanel::mention_or_attach`); pegar, soltar o adjuntar imágenes: ver "Imágenes" (Etapa 7).

## Imágenes (Etapa 7, `docs/specs/09-etapa7-conexiones-imagenes-comentarios.md` §5, subetapa E7-E)
- **Procesado** (`attachments.rs`, sin GPUI): `prepare_image(bytes, nombre) -> Result<PreparedImage, ImageError>` detecta PNG/JPEG/GIF/WebP por contenido; si el lado mayor es ≤ 2 000 px y pesa ≤ 10 MB manda los bytes originales; si no, reduce con Lanczos3 (orientación EXIF aplicada) y recodifica (PNG → PNG, JPEG → JPEG 85, WebP → PNG con transparencia o JPEG 85 sin ella, GIF → primer cuadro en PNG con aviso). Errores: `NotAnImage`, `TooLarge { bytes }`, `Unreadable(motivo)`, cada uno con su texto (`ImageError::message`). Constantes `MAX_IMAGE_SIDE`, `MAX_IMAGE_BYTES`, `MAX_IMAGES_PER_MESSAGE` (10), `JPEG_QUALITY`, `PICK_DIALOG_TITLE` ("Adjuntar imagen"), `PICK_DIALOG_FILTER` ("Imágenes"), `IMAGE_EXTENSIONS`. Crate `image` 0.25 (ya estaba en el árbol por GPUI; MIT OR Apache-2.0; sin crates nuevos en `Cargo.lock`).
- **Entrada** (las tres terminan en `ChatPanel::attach_images(Vec<AttachmentSource>)`): `Ctrl+V` (la caja toma `editor::paste` en captura: `ClipboardEntry::Image`, `ExternalPaths` con imágenes o un texto hecho solo de líneas `file://` — así llegan los archivos copiados en Wayland — se adjuntan; cualquier otro texto se pega como siempre); soltar archivos del explorador del sistema sobre la caja (`drag_over::<ExternalPaths>` pinta el borde en `border.focus`, `on_drop` → `attach_paths`); botón del clip (`chat::attach_image`, sin atajo) → `ChatEvent::PickImages`, el workspace abre `rfd` y llama `attach_paths(&paths, cx)`. Cada adjunto es `PendingAttachment { id, name, state: Processing | Ready(PreparedImage) }` (`ChatPanel::attachments`), procesado en el `background_executor`.
- **Capacidad**: `ChatPanel::set_image_support(Option<bool>)` (`None` = sin conexión); `handle_event(Connected)` ya la toma de `cincel_acp::agent_supports_images`, `Exited` la vuelve `None`. Sin conexión: "Conectá un agente para adjuntar imágenes"; sin imágenes: "«Nombre» no acepta imágenes" (nada se lee ni se adjunta). Con imágenes en el borrador y una conexión que no las acepta: línea "«Nombre» no acepta imágenes: quitá las imágenes para enviar" arriba de la caja y `Enter` no envía (`images_block_send`); mientras se preparan, "Preparando N imágenes…" y `Enter` espera (`is_preparing_images`).
- **Avisos**: `ChatEvent::Notify { level, text }` (el workspace los muestra como aviso emergente).
- **Envío**: texto y menciones, después un `PromptBlock::Image` por imagen lista, en orden; el mensaje guarda `MessageBlock::Image(ImageRef { file: "<sha256>.<ext>", name, mime_type, width, height, bytes_len, data })` con `data` `#[serde(skip)]`. `Conversation::images_to_store()` devuelve `(archivo, bytes)` para que el workspace los escriba en `conversations/<id>/images/`; el JSON nunca lleva base64.
- **Mensaje enviado**: miniaturas (≤ 96 px de alto, ≤ 160 de ancho) desde `data` o desde `<dir>/images/<file>` (`ChatPanel::set_conversation_dir`); si falta, "Imagen no disponible". Clic → `ChatEvent::OpenImage { source: ChatImageSource::File(ruta) | Bytes { mime_type, data }, name, width, height, bytes_len }` (el visor es del workspace, E7-G). Las imágenes que repite un `session/load` se muestran desde sus datos.
- **Versión**: `CONVERSATION_VERSION = 2`; `Conversation::migrate()` sube una versión 1 sin tocar sus datos (no tiene imágenes ni comentarios).

## Comentarios en el chat (Etapa 7, §6.6)
- Tipos propios (el chat no depende de `cincel-review`): `PendingComment { id, label, tooltip, path, line }` y `SentCommentCard { display_path, path, first_line, last_line, kind: SentCommentKind (Lines | RemovedBefore | DeletedFile), state_label, code, removed, truncated_lines, lang, text, not_sent }`; textos de estado `COMMENT_STATE_*`; `comment_tag_labels(&[TagSource])` arma "calc.py:24-28", "calc.py:24", "old.py (borrado)" (ruta relativa si dos archivos se llaman igual) y `comment_tag_tooltip` "src/calc.py, líneas 24 a 28" + texto (200 caracteres).
- `ChatPanel::set_pending_comments(Vec<PendingComment>)`: una etiqueta por comentario en una fila propia dentro de la caja, encima de las miniaturas y del texto, ordenadas por archivo y línea; la `×` emite `ChatEvent::RemoveComment { id }`, el clic `ChatEvent::OpenLocation { path, line }`. Enviar o empezar otra conversación no las quita: las quita el workspace al tomarlas.
- `ChatPanel::attach_sent_comments(Vec<SentCommentCard>)` las agrega al último mensaje como `MessageBlock::Comment` (tarjeta: archivo, líneas, estado, código en monoespaciada sobre `bg.editor`, 6 líneas y "… N líneas más" que despliega, texto; el encabezado emite `OpenLocation`); `mark_comments_not_sent()` agrega "No se envió: el comentario volvió al margen" (D16). Se guardan con la conversación.
- Selectores de pie: solo los del agente, uno por `ConfigOption` de categoría `mode`, `model`, `thought_level`; también `availableModes` legacy. Cambiar uno envía `SetConfigOption`/`SetMode` y refleja la respuesta. No hay selector de autonomía (Etapa 3).
- Aspecto de los mensajes (Etapa 3, correcciones): el del usuario es una burbuja contra el borde derecho con `text.accent` al 14 % sobre `bg.app`, borde de 1 px en `text.accent` al 35 %, radio 8 y ancho máximo del 85 %; el texto se parte al ancho de la burbuja, también un token largo sin espacios. La respuesta del agente es texto plano sobre el fondo del panel, sin burbuja ni regla. Los bloques de código de la respuesta van sobre `bg.editor` con borde de 1 px `border` y una cabecera chica con el lenguaje y "Copiar". Las tarjetas de herramienta siguen en `bg.surface`. No hay etiquetas "Vos" ni nombre del agente.
- Escala tipográfica única: cuerpo 13 px; código (en línea y en bloque) 12,5 px monoespaciado; filas de herramienta, plan y ayudas 12 px; etiquetas y fechas 11 px; encabezados del markdown como mucho 15 px. (El código en línea dentro de una respuesta queda en 0,875 × 13 ≈ 11,4 px: `gpui-kit` fija esa escala.)
- El transcript es una `gpui::list` que sigue el final: así `gpui-kit` mide los párrafos con código en línea con el tamaño del chat y no con el de la ventana.
- Estado de la conexión en cabecera (insignia `HeaderBadge`, solo con una conexión activa; desde la ronda 2 de la Etapa 7 ya no muestra la actividad del agente, que va en la fila al pie de la conversación: ver "Ronda 2 de la Etapa 7"); la barra de estado muestra la insignia de la conexión (la pinta el workspace).

## Conexiones (Etapa 4, `docs/specs/06-etapa4-conexiones-y-cincel.md` §4 F1, F4, F5, §6)
- **Encabezado**: donde estaba el selector de agente está el control **"Conectar"**. Sin conexión activa es un botón "Conectar"; con una, icono del proveedor (`provider_icon`: monograma C/X/G en un cuadrado redondeado), etiqueta, tipo de agente en gris, insignia de estado y caret (la identidad en gris que traía la Etapa 4 se retiró en la Etapa 7, ver más abajo; el tipo y la insignia del botón se retiraron en la ronda 2, que pinta aparte una única `HeaderBadge`: ver "Ronda 2 de la Etapa 7"). Los dos abren el popover.
- **Popover** (`Popover::Connections`): una fila por `ChatConnection { id, agent_id, agent_name, label, identity, last_used, badge }` con icono, etiqueta, tipo de agente en gris (Etapa 7: sin identidad ni "Usado hace…", que solo pinta Configuración) e insignia `ConnectionBadge` (Conectada / Sesión vencida en ámbar / No disponible, con el motivo en tooltip). Las filas vencidas llevan "Volver a conectar" y las no disponibles "Reparar". Clic derecho abre el menú contextual (`Popover::ConnectionMenu`) con "Renombrar". Al pie: "Conectar nuevo agente…" y "Eliminar conexión…". La fila activa (o, sin activa, la preseleccionada por `connections.default_label`) va resaltada.
- **El panel nunca conecta nada**: cada gesto es un `ChatEvent` (`ConnectionSelected { id }`, `NewConnection`, `DeleteConnections`, `RenameConnection { id }`, `Reconnect { id }`, `Repair { id }`) y el workspace decide. `set_connections`, `set_active_connection`, `set_preselected_connection`, `set_banner` y `set_status` son solo de presentación.
- **Estado vacío** sin conexión: "No hay ningún agente conectado" y botón "Conectar". Placeholder del compositor: "Conectá un agente para empezar…" / "Escribí un mensaje para «etiqueta»…".
- **Banner** (`ConnectionBanner`) sobre el transcript: "La sesión de «X» venció" con "Volver a conectar" (F4), o "«X» no está disponible: motivo" con "Reparar" (F5). Desde la Etapa 5 (`docs/specs/07-etapa5-productividad.md` §10.1), `ConnectionBanner::Expired` trae además `reason: Option<String>`: cuando el agente dio un motivo al pedir autenticación (`AgentEvent::AuthRequired.message`, ya redactado y recortado), debajo de "La sesión de «X» venció" se ve, en 12 px `text.muted`, "El agente dijo: «motivo»"; sin motivo, el banner se ve igual que antes.
- **Eventos ACP nuevos**: `AuthFailed` deja un aviso de error "No se pudo autenticar: …" (nunca se traga) y pone la insignia del encabezado en `autenticación requerida`; `AuthSucceeded`, `LoggedOut` y `ElicitationCompleted` dejan un aviso informativo.
- **Historial**: agrupado por la etiqueta de la conexión (`ConversationSummary.group`, con `connection_id`); las conversaciones anteriores a las conexiones (sin `connection_id`) van bajo `LEGACY_CONNECTION_GROUP` = "(conexión anterior)" y se abren de solo lectura (`LEGACY_HISTORY_NOTICE`). `Conversation.connection_id` se deserializa con `#[serde(default)]`, así que los archivos viejos siguen leyéndose.
- Persistencia: el transcript de la sesión actual se guarda en estado XDG por proyecto para restaurarlo al abrir (solo lectura hasta que el agente soporte `session/load`).

## Etapa 7: lista de conexiones y menús que se cierran solos (E7-A)

Spec: `docs/specs/09-etapa7-conexiones-imagenes-comentarios.md` §3 y §4.
Detalle y desviaciones en `docs/etapas/etapa-7.md`.

- **Lista más limpia**: `ChatConnection` suma `agent_name` (lo llena el workspace con `AgentKind::display_name`) y conserva `identity` y `last_used`, que el chat ya no pinta: los usa solo Configuración → Conexiones. El menú "Conectar" y el botón del encabezado muestran icono (16–18 px), nombre, tipo en gris (`visible_agent_type`: se omite si el nombre de la conexión es exactamente el tipo, sin distinguir mayúsculas, para no leer "Claude Claude") e insignia de estado (`connection_badge`). **Corregido por la ronda 2** (`10-etapa7-ronda2.md` §3 y §4): el botón del encabezado ya no lleva tipo ni insignia ni hay píldora de actividad; las filas del menú son de dos líneas y muestran el tipo siempre; la regla del tipo repetido (`visible_agent_type`) queda solo en la lista de "Eliminar conexión…" (workspace). La función `agent_type_label` de `render.rs` se eliminó.
- **Cierre de menús** (todos los `Popover`: `Connections`, `ConnectionMenu`, `Conversations`, `Config`, `Modes`, `Files` y `Commands`): un menú se cierra con clic fuera de su caja (`on_mouse_down_out`), cuando el foco pasa a otro elemento (editor, árbol, `Ctrl+L`, un modal; `cx.on_focus_out` del foco del menú, `popover_focus`, y del compositor para `@` y `/`), con `Esc` y cuando la ventana deja de estar en primer plano (`cx.observe_window_activation`). El defecto existía en todos, no solo en los dos del encabezado. Un clic en el mismo botón que abrió el menú lo cierra una sola vez y no lo reabre (`dismiss_popover` guarda `just_dismissed` junto con un contador de pulsaciones, `press_serial`, para que el clic siguiente sí lo abra). Al abrirse, los menús del encabezado y los selectores del pie toman el foco (`@` y `/` no: el usuario sigue escribiendo) y guardan quién lo tenía (`restore_focus`), que se devuelve al cerrar con `Esc` o al elegir una fila, no al cerrar porque el foco ya se fue a otro lado. El foco se mueve al pintar (`sync_popover_focus`); `toggle_popover` conserva su firma. Los menús de gpui-kit (barra de título, árbol) se cierran desde el workspace: `modulos/workspace.md`, "Etapa 7".
- Tests: `connections_view_tests.rs` (el texto de las filas y del botón no lleva identidad ni "Usado"; regla del tipo repetido; insignias) y `menu_dismiss_tests.rs` (clic fuera, foco fuera, `Esc`, ventana inactiva, clic en el mismo botón, elegir una fila con clic real sigue emitiendo `ConnectionSelected`).

## Ronda 2 de la Etapa 7 (`docs/specs/10-etapa7-ronda2.md`)

Correcciones y mejoras tras la prueba del autor, dentro de la misma 0.2.0.

- **Encabezado (§3)**: `model.rs::HeaderBadge { Connected, Disconnected, AuthRequired, SessionExpired, Unavailable { reason } }` con `label()` (en minúscula: "conectada", "desconectada", "autenticación requerida", "sesión vencida", "no disponible"). `ChatPanel::header_badge() -> Option<HeaderBadge>` (`None` sin conexión activa) decide por prioridad (sesión vencida > no disponible > autenticación requerida > desconectada > conectada) y **no** depende de la actividad del agente. `render.rs::header_badge_pill` pinta la insignia (selector `chat-header-badge`); el nombre completo de la conexión lleva `truncate` y tooltip (selector `chat-connection-name`). `agent_type_label` se eliminó de `render.rs` (el workspace usa `visible_agent_type` de `model.rs`, para la lista de "Eliminar conexión…").
- **Menú de conexiones (§4)**: filas de dos líneas (nombre arriba, tipo abajo siempre); selectores `connection-name-{i}` y `connection-type-{i}` (más `connection-badge-{i}`).
- **Imágenes (§5)**: en el mensaje enviado van arriba del texto; las tarjetas de comentario, debajo (`render_media.rs`: `render_message_images` y `render_message_cards`).
- **Fila de actividad (§8)**: `model.rs::AgentActivity { Thinking, Working, Writing, WaitingPermission }` con `label()` ("Pensando…", "Trabajando…", "Escribiendo…", "Esperando permiso…"). `ChatPanel::activity() -> Option<AgentActivity>` (`pub(crate)`) la deriva de la última señal del turno; es `None` fuera de un turno, durante la reproducción de `session/load` y cuando el último elemento es el pensamiento en vivo. No es una `Entry`: no se guarda. Se pinta al pie del último elemento (selector `chat-activity-row`).
- **Seguir el final (§9)**: el transcript usa `FollowMode::Tail` de la lista de GPUI. `ChatPanel::push` **ya no desplaza** (se quitó `scroll_to_end`); `set_follow_mode(FollowMode::Tail)` se llama solo al abrir una conversación (`load_conversation`), al empezar una nueva (`clear` / `start_new_conversation`), al enviar (`send`) y con la flecha (`jump_to_end`). Accesores: `is_following_tail()`, `shows_jump_to_end()` (`!siguiendo` y la lista no está al final) y `jump_to_end()`. El botón flotante lleva el selector `chat-jump-to-end` y la lista `chat-transcript`.
- **Bloques de código largos (§10)**: `code_folds.rs` (sin GPUI): `split_markdown(md) -> Vec<MdSegment>`, `MdSegment { range, kind }`, `SegmentKind { Prose, LongCode { lines, closed } }`, `CodeBlockKey { entry, piece, segment }`, constantes `CODE_FOLD_MIN_LINES = 21` y `CODE_FOLD_VISIBLE_LINES = 12` (y `CODE_FOLD_FADE_HEIGHT` = 40 px). `AgentText.segments: Vec<TextSegment>` (`TextSegment { range, kind, view }`, `#[serde(skip)]`) **reemplaza** al `view` único de antes; el JSON guardado no cambia. `ChatPanel.expanded_code_blocks: HashSet<CodeBlockKey>` recuerda los bloques desplegados (se vacía al abrir otra conversación o limpiar). `markdown.rs::text_view_style_folded(theme, scale, max_height)` da el estilo de un bloque plegado. Selectores `code-block-{e}-{p}-{s}` (la caja) y `code-fold-toggle-{e}-{p}-{s}` (el botón "Ver más (N líneas)" / "Ver menos").
- **Ya corregido (J)**: `ChatPanel::is_already_shown` ignora las menciones `@archivo` (`resource_link`) que el agente reproduce al retomar una sesión.
- Tests nuevos: `header_badge_tests.rs`, `connection_rows_tests.rs`, `message_media_order_tests.rs`, `activity_row_tests.rs`, `transcript_follow_tests.rs`, `code_fold_tests.rs` y los unitarios de `code_folds.rs`.

## Criterios de aceptación
- [ ] Con el agente falso de `cincel-acp`, el transcript muestra texto en streaming sin parpadeo y las tarjetas cambian de estado.
- [ ] Un pedido de permiso bloquea el envío de nuevos mensajes hasta responderlo; `Esc` lo rechaza.
- [ ] Cambiar el modelo desde el selector se refleja en la siguiente `configOptions` que devuelve el agente.
- [ ] `@` inserta `resource_link` con la ruta absoluta del archivo en el prompt enviado.
- [ ] El chat no muestra nunca un diff completo; la tarjeta enlaza al editor.
- [x] (E4) Sin conexión activa el encabezado muestra "Conectar" y el estado vacío "No hay ningún agente conectado"; elegir una fila emite `ConnectionSelected` y el panel no conecta nada por su cuenta (tests `without_a_connection_*`, `choosing_a_connection_*`, `the_popover_preselects_*`).
- [x] (E4) Un `AuthFailed` se muestra en el transcript (test `a_failed_authentication_is_shown_not_swallowed`).
